# Data Analyst Repositioning — Website + Résumé

**Date:** 2026-08-04

## Goal

Retarget Yuta Banishky's portfolio site and résumé from software-engineering
positioning to data-analyst positioning, for data analyst internship
applications.

## Context

- **Site:** `C:\Claude\Yuta Website` — static HTML/CSS/JS, deployed to Render,
  live at yutabanishky.com. Sidebar layout (Brittany Chiang-style), three
  sections: About, Experience, Projects.
- **Résumé:** `C:\Users\yutab\OneDrive\Documents\Resume\Yuta Resume.pdf`. No
  editable source exists — PDF only.

Current mismatch: the résumé is already ~70% analyst-oriented, but the site is
branded "Software Developer" with five web/product projects as the headline and
data analysis as a single trailing entry. A recruiter screening for analyst
roles reads the site as a web developer's portfolio.

## Known limitation

Yuta has exactly **one** genuine analysis project (Seattle Traffic Collision
Analysis). The AI CSV Data Analyzer is analytics *tooling*, not an analysis.
This repositioning maximizes existing material — it does not fabricate
projects, inflate metrics, or relabel engineering work as analysis.

Recorded recommendation, outside this scope: build one SQL-heavy analysis and
one with a BI dashboard (Tableau/Power BI) to fill the real gap.

## Decisions

| Decision | Choice |
|---|---|
| Title | "Data Analyst" — full commit, not a hybrid title |
| SE projects | Stay on the homepage, under a clearly secondary heading |
| Résumé source | Rebuilt as maintainable HTML, printed to PDF |
| PDF generation | Headless Chrome `--print-to-pdf` (Chrome confirmed installed) |

## Scope

### 1. Identity — `index.html`, `archive.html`

Both files carry a duplicated sidebar; both must change.

- `sidebar-title`: `Software Developer` → `Data Analyst`
- `sidebar-desc`: replace "I build things that ship — AI applications,
  computer-vision games, and full-stack web products" with an analysis-framed
  line (turning public datasets into decisions with Python and SQL).
- `<title>`, `<meta name="description">`, `og:title`, `og:description`,
  `og:image:alt`, `twitter:title`, `twitter:description` — all currently
  software-framed; rewrite data-first.

The `og-image.png` asset itself contains "Software developer" text and is
regenerated by `make_assets.py`; regenerate it to match.

### 2. About — `index.html`

- Lead with the Data Science track and the kind of analysis Yuta does, not
  "I build things that ship."
- Keep Bellevue Coding and Wilburton Soccer — founding and running things is a
  genuine signal. Trim the "AI applications, computer-vision games, real-time
  multiplayer" list that currently dominates.
- Reorder `skills-list` to lead with the analyst stack: Python, SQL,
  pandas / Matplotlib, Excel, R, statistical analysis. Next.js/React moves last.

### 3. Experience — `index.html`

The site is currently *weaker than the résumé* — it omits quantified results
the résumé already claims. Bring them over:

- **University Food Bank:** 340+ weekly orders analyzed; 18% reduction in
  stockouts on high-turnover items; 12% cut in overstock waste over one
  quarter; 200+ households served weekly.
- **UW Data Science Club:** 6 teams of 4–5 members; 3 completed projects per
  quarter; 50-member club.
- Add `Excel` / `R` tech pills where they genuinely apply.

### 4. Projects — `index.html`

Reorder so analysis leads:

- **"Data & Analysis"** becomes the primary heading, first on the page:
  1. Seattle Traffic Collision Analysis (existing card, keep the plain-language
     blurb — it reads well)
  2. AI CSV Data Analyzer — **promoted out of `archive.html` into a featured
     card.** Screenshot already exists at `assets/screenshots/csv.jpg`.
- **"Software & Product Projects"** becomes the secondary heading: Dubly,
  AI Poker Room, Yutachess, CineMate, KitNations.
- Where a software project has a genuine data dimension, surface it instead of
  UI polish (e.g. CineMate's Azure SQL). Do not overstate.

`archive.html` keeps every project including the CSV Analyzer — the archive is
a complete list, so featuring a project elsewhere doesn't remove it.

### 5. Résumé — new `resume/` directory

Rebuild as `resume/resume.html`: a self-contained file with inline print CSS
(US Letter, 0.5in margins, serif, single page) that reproduces the current
résumé's classic layout. This becomes the editable source that doesn't exist
today.

Content changes from the current PDF:

- **Summary line:** drop "and software engineering internships." Target data
  analyst roles only.
- **Skills:** lead with Languages (Python, SQL, R) and Data & Analysis
  (pandas, Matplotlib, Excel, statistical analysis, data cleaning &
  visualization). Demote Next.js/Node.js to a smaller tools line.
- **Projects:** Seattle Collision Analysis and AI CSV Data Analyzer first;
  Canvas SMS Study Assistant last and shortened.
- Keep all experience, education, and Other Experience entries as-is —
  they're accurate and the analyst framing already works.

Build step: `chrome --headless --print-to-pdf` → write to both
`assets/resume.pdf` (what the site links) and the OneDrive Resume folder.
Document the command in `README.md` so it's repeatable.

## Non-goals

- No new analysis projects (can't be fabricated).
- No layout, CSS architecture, or animation changes — this is content and
  ordering only, reusing existing components (`selected-project`,
  `tech-pill`, `exp-entry`).
- No changes to the deployed Render configuration.

## Verification

- Site renders correctly at desktop and mobile widths; no broken images or
  anchors after reordering.
- Zero remaining occurrences of "Software Developer" / "software engineering"
  in site copy or résumé.
- Generated `assets/resume.pdf` is a single page and legible.
